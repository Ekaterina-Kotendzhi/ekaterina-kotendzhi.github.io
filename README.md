# Портфолио — статическая версия для GitHub

Готовая к публикации копия сайта **без Node.js, Vite и `node_modules`**. Подходит для [GitHub Pages](https://pages.github.com/) и любого статического хостинга.

## Структура папки

Всё, что нужно для работы сайта, лежит в этой директории:

```
portfolio/
├── index.html          # разметка страницы
├── styles.css          # стили
├── script.js           # меню, анимация появления блоков
├── README.md           # эта инструкция
├── .gitignore          # служебные файлы ОС (не попадут в git)
└── assets/             # медиа и документы
    ├── photo.jpg       # фото в блоке «Обо мне»
    └── resume.pdf      # PDF для кнопок «Скачать резюме» / «Скачать PDF»
```

### Назначение файлов

| Файл | Назначение |
|------|------------|
| `index.html` | Одностраничный сайт: проекты, навыки, контакты, ссылки на GitHub |
| `styles.css` | Внешний вид (светлая тема, адаптив) |
| `script.js` | Мобильное меню, закрытие по Escape, анимация при прокрутке |
| `assets/photo.jpg` | Портрет в секции «Обо мне» (`src="assets/photo.jpg"`) |
| `assets/resume.pdf` | Резюме для скачивания (`href="assets/resume.pdf"`) |

Шрифты подключаются с Google Fonts по HTTPS — отдельно в репозиторий класть не нужно.

## Как выложить на GitHub (пошагово)

### Шаг 1. Создать репозиторий на GitHub

1. Откройте [github.com/new](https://github.com/new).
2. Имя репозитория, например: **`portfolio`** или **`Ekaterina-Kotendzhi.github.io`** (см. варианты URL ниже).
3. Репозиторий **Public**.
4. **Не** добавляйте README, `.gitignore` и license при создании (файлы уже есть локально).
5. Нажмите **Create repository**.

### Шаг 2. Загрузить файлы из папки `portfolio`

Откройте терминал в папке **`portfolio`** (именно внутри неё, где лежит `index.html`):

```powershell
cd c:\vibecoder\portfolio
git init
git add .
git commit -m "Add portfolio site for GitHub Pages"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

Замените `ВАШ_ЛОГИН` и `ИМЯ_РЕПОЗИТОРИЯ` на свои значения.

**Важно:** в git должны попасть файлы **из корня `portfolio/`**, а не вложенная папка `portfolio/portfolio/`. В корне репозитория на GitHub сразу должны быть `index.html`, `styles.css`, `script.js`, папка `assets/`.

### Шаг 3. Включить GitHub Pages

1. Репозиторий на GitHub → **Settings** → **Pages**.
2. **Build and deployment** → Source: **Deploy from a branch**.
3. Branch: **`main`**, папка: **`/ (root)`**.
4. **Save**. Через 1–3 минуты появится URL сайта.

## Локальный просмотр перед отправкой

GitHub не обязателен для проверки. Достаточно открыть `index.html` в браузере (двойной щелчок) или поднять простой сервер:

```powershell
cd c:\vibecoder\portfolio
npx --yes serve .
```

Откройте адрес из терминала (часто `http://localhost:3000`). Так надёжнее проверяются ссылки на `assets/resume.pdf`.

## Обновление контента

### Заменить фото

1. Положите новый файл в `assets/photo.jpg` (можно перезаписать).
2. Рекомендуемый формат: JPG, вертикальный кадр, сжатие для веба (чтобы репозиторий не раздувался).

Имя в HTML менять не нужно, если файл по-прежнему `assets/photo.jpg`.

### Заменить резюме

1. Замените файл `assets/resume.pdf`.
2. Имя оставьте **`resume.pdf`** — на него ссылаются обе кнопки скачивания.

### Изменить текст или ссылки

Редактируйте **`index.html`**, затем:

```powershell
git add .
git commit -m "Update contacts / projects"
git push
```

GitHub Pages обновится автоматически через 1–3 минуты.

### Синхронизация с основным проектом (`c:\vibecoder`)

Полная версия с Vite для локальной разработки живёт **на уровень выше** (`c:\vibecoder`). После правок в `index.html`, `styles.css` или `script.js` там:

1. Скопируйте изменённые файлы в `portfolio/`.
2. Обновите пути в копии `index.html`:
   - фото: `assets/photo.jpg` (не `images/avatar.jpg`);
   - PDF: `assets/resume.pdf` (не `resume_ekaterina_kotendzhi.pdf` в корне).
3. При смене фото/резюме скопируйте файлы в `portfolio/assets/`.

## Частые проблемы

### Сайт открывается, но нет фото или PDF (404)

- Файлы должны быть в **`assets/`**, с именами **`photo.jpg`** и **`resume.pdf`**.
- В `index.html` пути: `assets/photo.jpg` и `assets/resume.pdf` (без лишнего `/` в начале для корневого Pages).

### GitHub Pages показывает README вместо сайта

- В корне репозитория должен быть **`index.html`**, не только `README.md`.
- В Settings → Pages выбрана ветка **`main`** и папка **`/ (root)`**.

### Очень большой репозиторий

PDF и JPG увеличивают размер. Для GitHub обычно достаточно файлов до ~50–100 МБ суммарно; при необходимости сожмите фото (например, до 200–400 КБ) и PDF.

### `script.js` не работает при открытии файла как `file://`

Некоторые браузеры ограничивают модули с диска. Используйте локальный сервер (`npx serve .`) или сразу GitHub Pages по HTTPS.
